# フィットネスAI管理アプリ 要件定義書

## 1. プロジェクト概要

### 1.1 アプリケーション名
フィットネスAI管理アプリ（仮称）

### 1.2 目的
個人向けのフィットネス管理アプリケーション。AIを活用した食事管理とトレーニング管理により、ユーザーの目標達成をサポートする。

### 1.3 ユーザーターゲット
- **主なユーザー**: 個人利用者
- **使用シーン**: 
  - 自宅での食事・トレーニング管理
  - ジムでのトレーニング記録（スマホ入力）
  - 外出先（飲食店など）での食事記録（写真撮影）

## 2. 技術スタック

### 2.1 フロントエンド
- **フレームワーク**: Next.js 16.1.0 (App Router)
- **言語**: TypeScript
- **スタイリング**: Tailwind CSS 4
- **UI**: React 19.2.3

### 2.2 バックエンド
- **データベース**: Turso (SQLite)
  - ユーザーデータ
  - トレーニング記録
  - 食事記録
- **認証**: BetterAuth
  - Google認証

### 2.3 その他
- **決済**: ポーラー（将来実装予定）
- **AI機能**: 外部API（OpenAI/Claude等）
- **言語**: 日本語対応

## 3. 機能要件

### 3.1 食事管理機能

#### 3.1.1 カロリー・栄養計算
- **写真撮影による自動カロリー計算**
  - 食事の写真を撮影
  - AIが画像を解析してカロリーを自動計算
  - 外出先（飲食店など）での利用を想定
- **手動入力**
  - カロリーを手動で入力可能
  - データベース検索による食品情報の選択
- **栄養計算の詳細度**
  - マクロ栄養素（タンパク質、炭水化物、脂質）の記録
  - カロリー計算

#### 3.1.2 食事記録
- 1日3食 + 間食の記録
- 時間指定による記録
- 日々のカロリー摂取量の管理

#### 3.1.3 AI食事提案
- 目標（筋肉量アップ、ダイエット、運動不足改善）に応じた食事提案
- カロリー・栄養バランスを考慮した提案
- チャット形式での対話
- レポート形式での提案

### 3.2 トレーニング管理機能

#### 3.2.1 トレーニング記録
記録する項目：
- 種目
- 重量
- セット数
- レップ数
- 休憩時間
- RPE (Rate of Perceived Exertion)
- メモ

#### 3.2.2 部位別種目選び
- **初心者向け**: AI提案による種目選択
- **中級者以上**: フィルタリング機能による種目選択
  - 部位別フィルタ
  - お気に入り機能
  - 種目データベースからの選択

#### 3.2.3 トレーニングプラン
- **週次プラン**: 週単位のトレーニングスケジュール
- **部位分割**: 部位別のトレーニング分割（例：胸・背中・脚など）
- **AI生成プラン**: 目標に応じたトレーニングプランの自動生成

#### 3.2.4 重量管理
- 種目別の重量記録
- 目標重量の設定
- 重量達成予測（AIによる計算）
  - 例：「この種目をこのレップ数で続ければ、○ヶ月後に○kg達成可能」

#### 3.2.5 運動消費カロリー
- トレーニングによる消費カロリーの計算・記録

### 3.3 AIマネジメント機能

#### 3.3.1 目標別AI提案
目標タイプに応じた提案方法：
- **筋肉量アップ**: 高タンパク質食事、筋力向上トレーニング
- **ダイエット**: カロリー制限、有酸素運動
- **運動不足改善**: 軽めの運動、バランスの取れた食事

#### 3.3.2 AI機能一覧
- **食事提案**: カロリー・栄養バランスを考慮した提案
- **トレーニングプラン生成**: 目標に応じたプラン自動生成
- **進捗分析とアドバイス**: データ分析による改善提案
- **目標達成のための最適化提案**: 最適なアプローチの提案
- **重量達成予測**: トレーニングデータから目標重量達成時期を予測

#### 3.3.3 AI応答形式
- **チャット形式**: 対話型の質問・回答
- **レポート形式**: 分析結果や提案のレポート表示

### 3.4 目標設定と進捗管理

#### 3.4.1 目標タイプ

**減量（weight_loss）**
- 現在の体重と目標体重を設定
- ダッシュボードの体重グラフに目標ラインを表示
- 減量目標の自動計算

**増量（weight_gain）**
- 現在の体重と目標体重を設定
- ダッシュボードの体重グラフに目標ラインを表示
- 増量目標の自動計算

**筋力向上（strength）**
- 種目名を設定（ベンチプレス、スクワット、デッドリフト等）
- 現在の重量と目標重量を設定
- 目標達成までの差分を表示

**筋肉量アップ（muscle_gain）**
- 筋肉量（任意）：現在と目標の筋肉量（kg）
- ボディサイズ（任意）：
  - 腕回り（cm）
  - 胸囲（cm）
  - ウエスト（cm）
- 必要な項目だけ設定可能

#### 3.4.2 将来対応予定の目標タイプ
- 体重維持
- 持久力向上

#### 3.4.3 進捗可視化
- **グラフ表示**: 
  - 体重推移グラフ（目標体重ライン付き）
  - カロリー摂取・消費グラフ
  - トレーニング重量推移グラフ
- **レポート**: 
  - 週次・月次レポート
  - AI分析レポート

#### 3.4.4 体組成記録
- 体重
- 体脂肪率
- 筋肉量
- その他の体組成データ

#### 3.4.5 モチベーション機能
- 目標重量達成時に、有名なボディビルダー・アスリートの重量達成を通知
- 例：「あなたのベンチプレス100kgは、○○選手と同じ重量です！」

### 3.5 ソーシャル機能

#### 3.5.1 友達機能
- 友達追加機能
- 友達リストの管理

#### 3.5.2 競争機能
- **重量競争**: 種目別の重量を友達と競う
- **ダイエット競争**: 減量目標を友達と競う
- ランキング表示

### 3.6 通知・リマインダー機能
- 食事記録のリマインダー
- トレーニング予定の通知
- 目標達成時の通知

### 3.7 多デバイス対応
- **スマートフォン**: 主要デバイス（ジムでの入力に最適化）
- **PC**: 詳細なデータ分析・管理
- **タブレット**: 両方の中間的な用途
- **将来**: ネイティブアプリ化を検討

## 7. AI機能の実装方法

### 7.1 推奨アプローチ
**外部APIの使用を推奨**

理由：
- 自前モデルの構築には大量のデータ、計算リソース、専門知識が必要
- 開発期間が大幅に延びる
- コスト効率が悪い

### 7.2 推奨外部API
1. **OpenAI API**
   - GPT-4 Vision: 画像認識・カロリー計算
   - GPT-4: チャット形式のAI対話、プラン生成
   - すぐに接続可能、日本語対応良好

2. **Anthropic Claude API**
   - Claude 3.5 Sonnet with Vision: 画像認識
   - Claude 3.5 Sonnet: テキスト処理
   - 高品質な応答、日本語対応

3. **Google Gemini API**
   - Gemini Pro Vision: 画像認識
   - Gemini Pro: テキスト処理
   - コスト効率が良い

### 7.3 実装の容易さ
- 外部APIは**すぐに接続可能**
- Next.jsから直接APIを呼び出せる
- 環境変数でAPIキーを管理
- 実装例が豊富でドキュメントも充実

### 7.4 コスト考慮
- 使用量に応じた従量課金
- 初期段階では無料枠や低コストプランで開始可能
- スケールに応じて最適化可能
